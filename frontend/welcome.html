Engineering story · 2026-09-19 → 2026-09-20

The night our candles went dark.

Last weekend five paper strategies stopped receiving candles — silently, with no errors and no reconnects in the logs. What followed was a 28-hour debugging arc that uncovered five stacked bugs across two services and shipped four production fixes. This is the short version.

1

The watchdog that ate the candles

market_data's "no messages in 30s, reconnect" watchdog was tearing down the Redis pub/sub connection. Reconnecting on a timer — not on an actual fault — meant candle publishers and consumers were getting kicked off the bus in 30-second intervals.

Fix: split commands Redis onto its own connection, exception-based reconnect instead of silence-based · commit 107b83d
2

The bot that forgot it had strategies

Restart bot → running strategies vanish from memory. There was no startup hook to rehydrate running_strategy_instances from Redis. The "two-step restart" rule that lived in our runbook was a superstition — restarting both services just happened to work because the watchdog bug dominated.

Fix: alembic columns for run state, startup rehydrate via pub/sub · commits d6ec7ef → 31f8461 → 026cd64
3

The pub/sub subscription timing race

After the rehydrate fix, late-starting controllers still lost their own broadcasts. Pub/sub is at-most-once delivery, and we were publishing before subscribing — for every controller. The fix was to subscribe first, sleep a beat, then rehydrate.

Fix: move listener-task creation before rehydrate, add 1s settle · commit 24a8d1b
4

Paper-mode was secretly using testnet

The real killer: factory.py routed any controller with empty API creds to sandbox=True (testnet). Six other call sites in data_consumer.py re-wrote the exchange prefix unconditionally. Paper-mode candles were silently hitting a flaky testnet WS.

Fix: require both api_key AND api_secret for sandbox routing · commits e1d4097 + 05995c9
✓

The websocket that died without an error

The final layer: ccxt.pro's watch_ohlcv returns an empty list when OKX closes the socket after a historical backfill. The outer loop happily spins on empty results forever — no exception, no log. We added a silence watchdog (last_data_at = time.monotonic()) and a v2 that tears the task down to fully recover.

Fix: silence-watchdog v1 + v2 (tear-down not reconnect) · commits b108973 + 9e4394e

The lesson: when a single fix doesn't resolve the symptom, look for a second rewrite site before iterating on the same hypothesis. Two stacked bugs, two fixes needed. When a websocket reconnects inside the same loop, the loop is the bug — break out, pop the registry, let the orchestrator rebuild cleanly. Full postmortem in our blog →
